- **Task ID:** INV-006 — User & Minimal RBAC Foundation

## Summary

Added the database foundation for human user identities and organization-scoped roles. Authentication and login are not implemented.

## Models and enum

- `User`: UUID, globally unique email, optional display name, active flag, and timestamps.
- `OrganizationMembership`: UUID, organization and user relations, explicit role, active flag, and timestamps; one membership per user per organization.
- `OrganizationRole`: `ADMIN`, `BILLING`, `VIEWER`.

## Decisions and security

- Email is globally unique. Future application logic must normalize email to lowercase before storing or lookup.
- Role assignment is required and has no default.
- MVP1 intends one dedicated account with ADMIN; Krishna and working team members use BILLING; VIEWER remains available for future read-only use.
- The schema does not enforce a single ADMIN. Future application/service logic must protect the last active ADMIN from removal or demotion.
- Authentication may later map an externally authenticated email identity, such as Cloudflare Access, to `User.email`.
- No passwords, authentication provider, real users, or seed data were added.
